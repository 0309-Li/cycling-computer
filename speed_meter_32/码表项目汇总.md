## 二、项目整体概述

这是一个基于 **STM32F405RGT6** 的自行车骑行码表项目，主要功能包括：

- GPS 定位；
- 当前速度显示；
- 骑行距离统计；
- 骑行时间统计；
- 地图显示、拖动和缩放；
- 电池电量检测；
- 充电状态显示；
- 中英文切换；
- 深色模式切换；
- 实体按键控制；
- 外置 SD 卡保存地图；
- USB 大容量存储设备功能。

项目使用的主要软件和中间件包括：

- STM32 HAL；
- FreeRTOS；
- LVGL；
- FatFs；
- USB MSC；
- DMA；
- UART、SPI、I2C、ADC、SDIO 等外设。

整个项目可以抽象成下面这条链路：

```text
硬件外设
   ↓
HAL 驱动 / 中断 / DMA
   ↓
FreeRTOS 任务
   ↓
数据解析与业务计算
   ↓
LVGL Subject 数据模型
   ↓
Observer / Label / Map 控件
   ↓
LCD 屏幕显示
```

## 六、LVGL 主任务

`main_task_func()` 的主要代码逻辑如下：

```c
MX_USB_DEVICE_Init();

lv_init();

lv_tick_set_cb(xTaskGetTickCount);
lv_delay_set_cb(vTaskDelay);

lv_port_disp_init();
lv_port_indev_init();

f_mount(&SDFatFS, SDPath, 1);
ui_init();
```

### 1. LVGL 初始化

```c
lv_init();
```

LVGL 是图形库，本身并不知道 LCD、触摸屏和具体硬件接口，因此还需要完成显示和输入设备移植。

### 2. LVGL 时间系统

```c
lv_tick_set_cb(xTaskGetTickCount);
lv_delay_set_cb(vTaskDelay);
```

LVGL 需要时间基准来处理：

- 动画；
- 定时器；
- 控件刷新；
- 触摸处理；
- 延时。

本项目直接使用 FreeRTOS 的 Tick 作为 LVGL 时间来源。

### 3. LVGL 主循环

```c
for (;;)
{
    uint32_t tick = lv_timer_handler();
    osDelay(pdMS_TO_TICKS(tick));
}
```

`lv_timer_handler()` 是 LVGL 的核心调度函数，负责：

- 处理 LVGL 定时器；
- 处理动画；
- 处理输入事件；
- 处理控件树变化；
- 重新绘制需要刷新的区域；
- 调用显示驱动把像素发送到屏幕。

## 八、触摸屏输入流程

触摸屏使用 CST816，相关文件：

```text
E:\ShangGuiGu\learn_code\keil_32_code\vscode_cycling computer\speed_meter_32\Int\CST816.c
E:\ShangGuiGu\learn_code\keil_32_code\vscode_cycling computer\speed_meter_32\Middlewares\lvgl\lv_port_indev.c
```

硬件连接关系：

```text
CST816
   ↓ I2C2
STM32
```

触摸中断引脚配置为下降沿 EXTI。

触摸流程：

```text
手指触摸屏幕
   ↓
CST816 INT 引脚产生下降沿
   ↓
STM32 外部中断
   ↓
CTP_INT_IRQHandler()
   ↓
is_pressed = true
   ↓
LVGL 调用 touchpad_read()
   ↓
CST816_Read()
   ↓
I2C 读取 X/Y 坐标
   ↓
LVGL 处理点击、拖动和滑动
```

中断函数只设置标志位：

```c
void CTP_INT_IRQHandler(void)
{
    is_pressed = true;
}
```

真正的 I2C 读取在 LVGL 读取输入时执行：

```c
CST816_Read((uint16_t *)x, (uint16_t *)y);
```

这种设计可以避免在中断中执行耗时的 I2C 通信。

## 十、Subject 和 Observer 数据绑定

项目定义了一个统一的数据结构：

```c
typedef struct
{
    lv_subject_t gps;
    lv_subject_t sport_status;
    lv_subject_t battery_level;
    lv_subject_t speed_sub;
    lv_subject_t mile_sub;
    lv_subject_t slope_sub;
    lv_subject_t latitude;
    lv_subject_t longitude;
    lv_subject_t min_sub;
    lv_subject_t sec_sub;
} speed_meter_sub_t;
```

可以把它理解成：

```text
码表当前运行状态
```

其中包括：

- GPS 卫星数量；
- 运动状态；
- 电池图标；
- 当前速度；
- 骑行距离；
- 坡度；
- 经纬度；
- 骑行时间。

例如速度 Label：

```c
lv_label_bind_text(speed_label,
                   &speed_meter_sub->speed_sub,
                   "%.1f km/h");
```

后台只需要修改 Subject：

```c
lv_subject_set_float(&speed_meter_sub->speed_sub, velocity);
```

Label 就会自动更新。

这就是：

```text
Subject：数据源
Observer：观察者
Widget：显示控件
```

相比后台直接调用 `lv_label_set_text()`，Subject/Observer 方式把数据和界面解耦了。

## 十四、GPS 数据链路

GPS 文件：

```text
E:\ShangGuiGu\learn_code\keil_32_code\vscode_cycling computer\speed_meter_32\Int\GPS.c
```

硬件使用：

```text
GPS 模块：AT6558
串口：USART2
波特率：9600
接收方式：DMA 循环接收
```

完整链路：

```text
AT6558 GPS 模块
   ↓ USART2
DMA 循环接收
   ↓
DMA 半传输 / 全传输回调
   ↓
复制到 gps_buffer
   ↓
通知 gps_task
   ↓
解析 NMEA 数据
   ↓
更新 Subject
   ↓
界面自动刷新
```

### 1. DMA 缓冲区

```c
#define GPS_BUF_LEN 128
#define GPS_DMA_BUF_LEN 16

static uint8_t usart2_dma_buffer[GPS_DMA_BUF_LEN];
static char gps_buffer[GPS_BUF_LEN];
```

DMA 缓冲区长度为 16 字节，当接收到前 8 字节时触发半传输回调，接收完 16 字节时触发完成回调。

### 2. DMA 回调

回调函数：

```c
GPS_UART2_HalfRecvCallback()
GPS_UART2_RecvCallback()
```

回调中把数据复制到软件缓冲区，并通知 GPS 任务：

```c
vTaskNotifyGiveFromISR(gps_taskHandle,
                       &xHigherPriorityTaskWoken);
```

这里体现的思想是：

> 中断中只进行快速数据搬运和任务通知，字符串解析放到任务中执行。

### 3. GPS 任务等待通知

```c
ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
```

GPS 任务没有数据时处于阻塞状态，收到 DMA 通知后才开始解析，这样可以避免无意义轮询。

### 4. GGA 语句

GGA 语句提供：

- 纬度；
- 纬度方向；
- 经度；
- 经度方向；
- 定位状态；
- 卫星数量。

项目使用 `strtok()` 按逗号拆分字段。

GPS 的经纬度格式通常是：

```text
DDMM.MMMM
```

转换为十进制度：

```text
度 + 分 / 60
```

例如：

```text
4006.1302,N
```

转换为：

```text
40 + 6.1302 / 60
```

### 6. VTG 语句

VTG 语句主要用于获取运动速度：

```c
velocity = atof(token);
```

速度单位为 km/h。

距离计算公式：

```c
distance += velocity * seconds / 3600.0f;
```

因为：

```text
速度单位：km/h
时间单位：秒
距离单位：km
```

所以需要除以 3600。

### 7. 运动状态和骑行时间

速度大于 0.5 km/h 时认为正在运动：

```c
if (velocity > 0.5f)
{
    distance += velocity * seconds / 3600.0f;
    ride_time_s += seconds;
    status = 1;
}
else
{
    status = 0;
}
```

状态数组：

```c
char *sport_status[] = {
    "stop",
    "running",
    "pause"
};
```

后台任务使用：

```c
lv_async_call(...);
```

把界面更新动作转回 LVGL 所在线程。

## 十五、为什么 GPS 任务要使用 `lv_async_call`

LVGL 通常要求由同一个线程或任务操作控件。

GPS 任务不应该直接执行：

```c
lv_label_set_text(...);
lv_obj_del(...);
lv_obj_set_style_...( ... );
```

否则可能出现：

- 界面崩溃；
- LVGL 对象树损坏；
- 随机死机；
- 内存访问异常。

本项目采用：

```text
GPS 任务负责采集和计算
   ↓
lv_async_call()
   ↓
LVGL 任务负责更新 Subject
   ↓
控件自动刷新
```

这是后台数据任务和 GUI 任务之间的正确协作方向。


```c
Key_RegisterCallback(KEY_POWER, Power_Off, NULL);
```

按下电源键后，最终关闭：

```c
HAL_GPIO_WritePin(POWER_EN_GPIO_Port,
                  POWER_EN_Pin,
                  GPIO_PIN_RESET);
```

## 十七、电源和电池检测

电源文件：

```text
E:\ShangGuiGu\learn_code\keil_32_code\vscode_cycling computer\speed_meter_32\Int\Power.c
```

电源任务每 100 ms 执行一次：


### 1. 充电状态检测

```c
return HAL_GPIO_ReadPin(CHG_DET_GPIO_Port,
                        CHG_DET_Pin) == GPIO_PIN_RESET;
```

当前设计是低电平代表正在充电。

### 2. ADC 检测电池电压

电池通过电阻分压后接到：

```text
PA1 / ADC1_IN1
```

ADC 为 12 位，因此满量程为 4096：

```c
return ((float)(val * 2)) / 4096.0f * 3.3f;
```

换算过程：

```text
ADC 输入电压 = ADC 数值 / 4096 × 3.3V
电池实际电压 = ADC 输入电压 × 2
```

### 3. 电池图标

正在充电时显示：

```c
LV_SYMBOL_CHARGE
```

没有充电时，根据电压估算百分比并选择：

```text
空电池
一级电量
二级电量
三级电量
满电池
```

## 十九、LDO 和 DC/DC 知识点

笔记中还补充了电源部分。

### LDO

LDO 是低压差线性稳压器，例如把 5V 降到 3.3V。

特点：

- 电路简单；
- 噪声低；
- 纹波小；
- 成本低；
- 效率较低；
- 多余电压以热量消耗。

例如：

```text
5V → 3.3V
```

### DC/DC

DC/DC 通过高频开关、MOS 管、电感和电容实现电压转换。

特点：

- 效率高；
- 发热小；
- 适合大电流和大压差；
- 电路相对复杂；
- 可能产生纹波和 EMI。

核心概念是占空比：

```text
平均输出电压 ≈ 输入电压 × 占空比
```

## 二十一、当前源码中需要注意的问题

### 1. 坡度功能目前还没有真正实现

项目界面已经有坡度 Subject 和坡度 Label：

```c
lv_subject_init_float(&speed_meter_sub->slope_sub, 0.0);
```

但是当前没有看到：

- 陀螺仪初始化；
- 姿态数据读取；
- 坡度计算；
- `slope_sub` 更新。

所以当前状态更像是：

```text
坡度 UI 已预留
陀螺仪业务逻辑尚未接入
```

### 2. GPS 第一次时间计算可能不准确

当前：

```c
static uint32_t last_tick_count;
```

初始值为 0。第一次收到 VTG 数据时，可能把设备启动到第一次 GPS 数据到达之间的时间全部算入骑行时间和距离。

更合理的做法是第一次收到速度时只初始化时间戳，后续数据再计算时间差。

### 3. 电池百分比需要限制范围

当前代码：

```c
battery_level_str[percent / 20]
```

如果测量误差导致 `percent > 100`，可能数组越界。实际使用时应该先把百分比限制在 0 到 100 之间。

### 4. GPS 缓冲区要注意并发和越界

DMA 回调和 GPS 任务同时访问：

```c
gps_buffer
gps_buffer_index
```

需要注意：

- 缓冲区不能被覆盖；
- 字符串要正确添加 `\0`；
- 一次接收多条 NMEA 语句时要逐行处理；
- 缓冲区满时不能继续写入；
- DMA 写入和任务解析之间要避免竞争。

### 5. LVGL 要尽量由单独任务操作

后台任务只负责：

```text
采集数据
计算数据
修改业务变量
```

LVGL 任务负责：

```text
Subject 更新
控件创建和删除
样式修改
屏幕刷新
```

## 二十二、用一段话串起整个项目

设备上电后，STM32F405RGT6 首先完成 HAL、系统时钟和各种外设初始化，然后启动 FreeRTOS。FreeRTOS 创建 LVGL 主任务、按键任务、电源任务和 GPS 任务。LVGL 主任务初始化 LCD、触摸屏、SD 卡和整个 UI，随后不断调用 `lv_timer_handler()`，负责处理事件、控件变化和屏幕刷新。

GPS 模块通过 USART2 和 DMA 持续发送 NMEA 数据，DMA 半传输或全传输完成后触发回调，把数据放入缓冲区并通知 GPS 任务。GPS 任务解析 GGA 和 VTG 语句，得到卫星数、经纬度和速度，再计算距离、骑行时间和运动状态。后台数据不会直接操作 LVGL，而是通过 `lv_async_call()` 回到 LVGL 任务中，修改 `speed_meter_sub` 中的 Subject。界面上的 Label、状态文字和地图通过 Observer 自动感知 Subject 变化并刷新。

触摸屏通过 I2C2 读取坐标，实体按键任务通过 GPIO 扫描并消抖，电源任务通过 GPIO 和 ADC 检测充电状态与电池电压。GPX 页面则根据当前经纬度转换出地图像素坐标和瓦片坐标，从 SD 卡加载周围 9 张地图图片，同时支持拖动、缩放和回到当前位置。最终，所有数据都汇聚到 LVGL 的控件树中，再由 SPI1 + DMA 刷到 ST7789 LCD 上。

完整主线：

```text
STM32 外设采集数据
        ↓
FreeRTOS 任务调度
        ↓
GPS / 电源 / 按键数据处理
        ↓
LVGL Subject 数据模型
        ↓
Observer 自动更新控件
        ↓
地图、速度、距离、电量、状态显示
        ↓
SPI + DMA 刷新 LCD
```
